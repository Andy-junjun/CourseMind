# 训练评估与实验方法

来源依据：Deep Learning Book 在线版、PyTorch 教程、常见信息检索评估方法。本文为中文改写整理，不复制原文。

参考链接：

- https://www.deeplearningbook.org/
- https://pytorch.org/tutorials/
- https://faiss.ai/

## 1. 为什么要做评估

深度学习项目不能只展示“能跑”。如果没有评估，就无法说明模型是否真的有效。CourseMind 至少需要评估两个层面：

```text
检索是否找到正确资料
生成回答是否基于证据且覆盖要点
```

检索评估比生成评估更容易量化，因此应优先建立稳定的 `questions.csv`。

## 2. 训练集、验证集和测试集

训练集用于更新模型参数，验证集用于选择超参数和早停，测试集用于最终报告。小项目中数据量有限，也应该保留一部分问题不参与训练，只用于最终评估。

错误做法：

```text
把所有问题都用于训练
只看训练集命中率
微调后不做新问题测试
```

正确做法：

```text
按主题分层划分问题
训练问题用于构造 pair
验证问题用于调参
测试问题用于最终展示
```

## 3. Recall@K

Recall@K 衡量正确资料是否出现在 Top-K 检索结果中。例如 Recall@5 表示前 5 个结果里是否包含 expected_file 或 expected_topic。

对 CourseMind 来说，可以比较：

```text
BM25
FAISS embedding
FAISS + BM25
FAISS + BM25 + GraphRAG
FAISS + BM25 + GraphRAG + MiniRanker
```

如果 GraphRAG 和 MiniRanker 有效，Recall@5 或 MRR 应该提升，或者至少在案例分析中能解释为什么最终证据更合理。

## 4. MRR

MRR 即 Mean Reciprocal Rank。它关注正确答案第一次出现的位置。如果正确资料排第 1，得分是 1；排第 2，得分是 1/2；排第 5，得分是 1/5。MRR 比 Recall@K 更关注排序质量。

MiniRanker 的目标就是把更相关的证据排到更前，所以 MRR 是合适指标。

## 5. 消融实验

消融实验通过移除某个模块观察性能变化，判断模块是否有贡献。CourseMind 可以做：

```text
无 BM25 vs 有 BM25
无 GraphRAG vs 有 GraphRAG
无 MiniRanker vs 有 MiniRanker
base embedding vs fine-tuned embedding
```

如果某个模块没有提升，需要解释原因，可能是数据太少、问题太简单、特征权重不合理或评测集覆盖不足。

## 6. 对 CourseMind 的意义

汇报时不要只说“我们用了 FAISS 和 GraphRAG”。更有说服力的说法是：

```text
我们构建了带标注问题的数据集
用这些问题生成 embedding 微调 pair
用 Recall@5 和 MRR 比较模块效果
用可视化展示 GraphRAG 扩展路径
用引用来源约束大模型回答
```

这样老师能看到系统工程和深度学习实验方法，而不是只看到一个问答网页。
